# 02 架构说明（TOGAF 四域视角）

> 项目：泵类设备故障诊断分类

| TOGAF 域 | 本项目答案 |
|---|---|
| 业务架构 | 车间泵类设备三态自动判别 → 值班师傅据混淆矩阵决定复核强度 |
| 数据架构 | 真实 `data/pump_fault.csv`（450×5，三类均衡）；纯 NumPy 分层划分；缺数据时降级合成兜底并在报告中标注；输出混淆矩阵、四项指标与决策矩阵 JSON |
| 应用架构 | core 加载/划分/训练三模型/手写指标/决策矩阵；pipeline 编排并落盘 |
| 技术架构 | Python 3.12+ / conda ai01；numpy + scikit-learn（LR/DT/RF）；pytest |

## 分层与模块职责
| 模块 | 职责 | 关键接口 |
|---|---|---|
| `core.py` | 数据加载、分层划分、训练评估、手写指标、决策矩阵 | `load_labeled_csv()/stratified_split()/evaluate()/metrics_from_confusion()/decision_matrix()/tier_of()` |
| `pipeline.py` | 三模型对比流水线 | `run(cfg, out_dir)` / `build_models(cfg)` |

## 依赖方向
```
run.py  →  pipeline  →  core（纯函数，零依赖）
               ↓           ↑
            io_utils ←── report
               ↑
            config（YAML 驱动）
```
**规则**：下层不得反向依赖上层；`core` 只在函数内延迟 `import io_utils` 且仅用 `read_csv_rows()` 读表，
**不做路径解析**（`course_data()` 留在 pipeline），因此单测可直接传 `tmp_path` 文件而不必 mock 数据目录。

## 关键质量属性
- **可测试性**：core 为纯函数 → 单测无需 mock 文件系统
- **可配置性**：阈值全部外置 YAML
- **可复现性**：种子固定于配置
