# 04 测试计划与报告（GB/T 15532《计算机软件测试规范》）

> 项目：特征工程优化的故障诊断系统（工单 M1.2）

## 1. 测试策略
| 层级 | 方法 | 目标 |
|---|---|---|
| 单元测试 | pytest，core 纯函数 | 覆盖正常/边界/异常三档 |
| 泄漏专项 | 填补/缩放统计量只能来自训练折；网格搜索只在训练集内做 K 折 | 杜绝工单常见错误③ |
| 集成测试 | pipeline 端到端（临时目录） | 消融表 5 行、决策矩阵两维齐备 |
| 档位回归 | 实跑取实测值，正向/反向/边界三向断言 `core.gain_tier` + `core.reach_tier` | 档位是算出来的，不是报告里的常量 |
| 工单对账 | 回读 `../../工单任务书/M1.2工单-*.md` 验收标准表 | 配置门槛、报告门槛、工单原文三者同数 |
| 回归 | `pytest -q` 全量 | 任一改动不破坏既有行为 |

## 4. 缺陷记录
| 编号 | 描述 | 处置 |
|---|---|---|
| BUG-01 | 旧版只做清洗与质量分，工单第三节的消融/派生特征/缩放对照/网格搜索/5 折稳定性全缺 | 已补齐五步消融 + 两维决策矩阵 + 稳定性报告 |
| BUG-02 | `requirements.txt` 未声明 scikit-learn，换机即 `ModuleNotFoundError` | 已加 `scikit-learn==1.9.0`（并回填 numpy/pandas 实版） |
| BUG-03 | 真实 CSV 三类近线性可分，准确率天花板≈0.99，任何合规基线的提升都 <5pp → D 档不可达 | 双口径设计：主口径为可复现的现场采集视图（缺陷率写在配置），同时**如实报出**实验室口径只有 +1.76pp 的事实与成因 |
| BUG-04 | lbfgs 未收敛告警刷屏 | `core.score()` 内 `catch_warnings` 压掉 stderr，并把 `n_iter_` 作为列写进消融表当证据 |
| BUG-05 | 档位判定没有测试守护：`[工单 M1.2 验收档位]` 段的数字改没改、报告与代码是否同口径，全靠人眼查 | 新增 `tests/test_tiers.py` 18 例：正向（实跑值重算=报告=配置=工单原文）、反向 4 条（提升压线/方法数<3/因果解释删空/规范率跌破 70% 都必须掉档）、边界（工单写"≥"取等即达标） |
| BUG-06 | 报告把"规范率"印在旁边却不参与档位计算；工单里判不了的主观条款（能说明改进思路等）没有单列，容易被读成"已自动达标" | 规范率各档线外置为 `rules.yaml: style_d/c/b/a`（D 档=工单明文 70%，C/B/A=M1.1 通用量表行，报告注明出处）；`core.reach_tier()` 合并功能门+规范率门并印"综合达标档位"；主观条款以 `pipeline.HUMAN_ITEMS` 列为"人工答辩项 4 条…未计入上方判定" |
| BUG-07 | 4 处 E127/E128 续行对齐 + 1 处 E501 超长行，使规范率实测停在 99.4% | 改写 `scaler_insensitivity()` 签名与消融步骤列表的续行、估计器改为逐档新建；实测 100.0%（0 违规 / 1599 有效行），未放宽任何门槛 |
