# 03 设计说明

> 项目：特征工程优化的故障诊断系统（工单 M1.2）

## 1. 模块清单与接口
| 模块 | 职责 | 关键接口 |
|---|---|---|
| `core.py` | 真实数据加载 / 现场视图注入 / 流水线装配 / 评分 / CV / 网格搜索 / 档位判定 | `load_pump_csv()/field_view()/violation_report()/derive_features()/build_steps()/score()/cv_stability()/grid_search()/scaler_insensitivity()/gain_tier()` |
| `pipeline.py` | 双口径消融流水线 | `run(cfg, out_dir)` / `run_ablation()` / `run_lab_ablation()` |
| `io_utils.py` | CSV/JSON、原子写、CJK 等宽表、课程数据定位 | `course_data()/fmt_table()/write_text()/write_json()` |
| `config.py` | YAML 加载 + Settings（含 `yaml_lite` 兜底） | `load_config(path)` |

## 2. 核心算法/规则
1. **加载**：`io_utils.course_data("pump_fault.csv")` 依次尝试 `AI_COURSE_DATA` → `../../data` → `../data` → `./data`；
   未命中 `pipeline.run()` 直接 `FileNotFoundError`——本项目**不做合成兜底**，因为验收口径是"真实数据上的提升幅度"，造数会让数字失真。
2. **划分**：纯 NumPy 分层抽样（每类 shuffle 后按 `test_size=0.25` 取整进测试集），`seed` 取自配置。
3. **现场采集视图（口径A）**：`field_view(X, seed, miss_rate, spike_rate)` 把随机单元写 0（模拟 PLC 掉线）并把随机行的 `temp_c` 置为 135℃（满量程尖峰）；
   缺陷率写在 `config/rules.yaml`，设为 0 即回实验室口径。设计动机见 docs/07 ADR-002。
4. **量程校验**：`PHYS_RANGES` 给出每列物理合理区间；`violation_report()` 分别计 `below_zero_or_missing` 与 `out_of_range`，用于报告"采集缺陷 vs 真实工况"的判定依据。
5. **流水线装配**：`build_steps(impute, derive, scaler, model_cfg)` 把 `SimpleImputer(missing_values=0.0, median)`、
   `DeriveTransformer`、`StandardScaler|MinMaxScaler`、`LogisticRegression` 串成一条 sklearn `Pipeline`；
   由于 fit 只在训练折上发生，填补中位数与缩放参数天然不含测试信息（工单常见错误①③）。
6. **派生特征**：`vib_over_current = vibration/(current+eps)`（同一故障下振动升高、电流下降，比值放大差异）、
   `temp_x_pressure = temp*pressure`（出口压力做功发热，联合刻画叶轮堵塞导致的背压升高）。
7. **评分**：`score()` 返回 acc、macro-F1、lbfgs 实际迭代数 `n_iter`、各类召回；
   `ConvergenceWarning` 在函数内压掉并改以 `n_iter` 列形式写进消融表——"未缩放→不收敛→基线弱"本身是要交给学生的证据。
8. **缩放对照**：`scaler_insensitivity()` 跑 none/standard/minmax × 逻辑回归（主算法）与随机森林（对照），
   实测树模型三档 acc 逐位相同，直接证伪"对树模型做归一化有收益"（工单常见错误②）。
9. **调参**：`grid_search()` 用 `StratifiedKFold(5)` 只在训练集内切折搜 `model__C`，报每档训练折内 CV 均值并标选中档；
   交付依据是训练折证据，测试集只在最后评一次。
10. **稳定性**：`cv_stability()` 给训练集 5 折 accuracy 的 mean±std 与各折明细，用于解释"CV 最优≠测试最优"的正常抖动。
11. **档位判定**：`gain_tier(gain_pp, f1_macro, n_methods, has_causal_note, gates)`；
    门槛 D≥5pp / C≥7pp / B≥10pp 且 macro-F1≥0.80 / A 需 ≥3 种方法 + 因果解释，全部取自 `config/rules.yaml`。
12. **综合档位**：`reach_tier(flags, style_rate, style_gates)`——工单 D 档除"提升≥5%"外还明文写了"规范率≥70%"，
    C/B/A 档的规范率线工单未写、取 M1.1《通用量表·代码规范》行 70/80/90（都外置在 rules.yaml 的 `style_d/c/b/a`）。
    功能门与规范率门**都过**才算达标，规范率由 `stylecheck` 实测喂入，报告同时印出"仅功能门档位"便于对账。
13. **人工答辩项**：工单里"能说明改进思路""交叉验证报告规范""因果解释是否成立""噪声样本处理策略合理"
    四条无法用数字判定，`pipeline.HUMAN_ITEMS` 显式列在报告档位段并标注"未计入上方判定"——
    代码只验证"因果解释这段文字存不存在"，判不了"讲不讲得通"，所以不替学生自动宣布达标。

## 3. 异常处理策略
| 异常 | 触发场景 | 处理 | 对应测试 |
|---|---|---|---|
| FileNotFoundError | 配置文件缺失 | 抛出并提示路径 | test_config.py::test_missing_config_raises |
| FileNotFoundError | 课程数据 `pump_fault.csv` 找不到 | 明确提示可用 `AI_COURSE_DATA` 指定，绝不静默造数 | test_pipeline.py::test_missing_data_raises |
| ValueError | CSV 缺少必需特征/标签列 | 启动即拒绝并列出实际列名 | test_core.py::test_load_bad_columns_raise |
| KeyError / IndexError | gates 字典缺档（调用方绕开 pipeline 直接调 `gain_tier`） | 不做静默补零，缺档就报错，逼调用方把配置写全 | test_core.py::test_gain_tier_boundaries |
| 配置缺键 | rules.yaml 未写 gain_d / cv_folds / miss_rate 等 | pipeline 用 `r.get(key, 默认)` 兜底，默认值=工单门槛（5/7/10pp、5 折、0.15/0.03） | test_config.py::test_settings_defaults_fill |
| 空输入 | 数据文件 0 条记录 | `load_pump_csv` 抛 `ValueError("数据文件为空…")`，不让空数组流进消融表 | test_core.py::test_load_empty_csv_raises |

## 4. 命名与代码规范
- PEP 8；`snake_case`（函数/变量）、`PascalCase`（类）、`UPPER_CASE`（常量）
- docstring 三件套：做什么 / 参数 / 返回
- 单元函数 ≤40 行，超过则拆分
- sklearn 依赖延迟 import（函数内），保证 `core` 的纯函数可被单测与降级检查独立使用
