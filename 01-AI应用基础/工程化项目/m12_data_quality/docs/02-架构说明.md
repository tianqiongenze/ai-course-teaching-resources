# 02 架构说明（TOGAF 四域视角）

> 项目：特征工程优化的故障诊断系统（工单 M1.2）

| TOGAF 域 | 本项目答案 |
|---|---|
| 业务架构 | 车间要求"不换算法也能提精度"：把清洗/特征/缩放/调参的收益量化到百分点，值班工程师据此决定先修数据还是先修模型 |
| 数据架构 | 真实 `data/pump_fault.csv`（450×5，三类各 150）→ 现场采集视图（掉线 0 值 + 135℃ 满量程尖峰，种子可复现）→ 训练折内填补/派生/缩放后的特征矩阵；输出消融表、缩放×模型对照表、超参档位表、5 折稳定性 |
| 应用架构 | core 做加载/视图注入/流水线装配/评分/CV/网格搜索/档位判定；pipeline 编排五步消融 + 口径B对照 + 报告落盘 |
| 技术架构 | Python 3.10+ / conda 环境；numpy + pandas + scikit-learn（Pipeline/SimpleImputer/StandardScaler/MinMaxScaler/GridSearchCV/StratifiedKFold）；pytest |

## 分层与模块职责
| 模块 | 职责 | 关键接口 |
|---|---|---|
| `core.py` | 数据加载、现场视图注入、流水线装配、评分、CV、网格搜索、档位判定 | `load_pump_csv()/field_view()/build_steps()/score()/cv_stability()/grid_search()/scaler_insensitivity()/gain_tier()/reach_tier()` |
| `pipeline.py` | 消融流水线 + 双口径对照 | `run(cfg, out_dir)` / `run_ablation()` / `run_lab_ablation()` |
| `io_utils.py` | CSV/JSON、原子写（`write_text` 先写临时文件再 `os.replace`）、CJK 等宽表、课程数据定位 | `course_data()/fmt_table()/write_text()/write_json()` |
| `report.py` | 分节渲染并落盘 | `render(sections)` / `save(sections, path)` |

## 依赖方向
```
run.py  →  pipeline  →  core（领域逻辑，sklearn 在函数内延迟 import）
               ↓           ↑
            io_utils ←── report
               ↑
            config（YAML 驱动：缺陷率、C 网格、折数、四档门槛）
```
**规则**：下层不得反向依赖上层；`core` 只在函数内延迟 `import io_utils` 且仅用 `read_csv_rows()` 读表，
**不做路径解析**（`course_data()` 留在 pipeline），因此单测可直接传 `tmp_path` 文件而不必 mock 数据目录。

## 关键质量属性
- **无泄漏**：`build_steps()` 把填补/派生/缩放装进同一条 sklearn `Pipeline`，`fit` 只见训练折；`grid_search()` 的 CV 折由训练集内部 `StratifiedKFold` 切出。
- **可归因**：五步消融一次只加一步，收益以百分点记账；`n_iter_`（lbfgs 迭代数）作为"未缩放导致不收敛"的成因证据。
- **可配置**：`miss_rate/spike_rate` 设 0 即回到实验室口径，代码不改。
- **诚实口径**：口径A（现场）与口径B（实验室原样）同时出表，不挑好看的数字交付。
- **可复现**：划分、缺陷注入、CV 折全部固定种子（`cfg.seed`，测试视图用 `seed+1`）。
