# 02 架构说明（TOGAF 四域视角）

> 项目：数据清洗与质量评分

| TOGAF 域 | 本项目答案 |
|---|---|
| 业务架构 | 把'脏日志'变成'可信数据集'，是后续一切模型与看板的地基 |
| 数据架构 | 带脏的 (ts, vib, temp) 时序 → 清洗后数据集 + 三类问题清单（缺失/异常/重复）+ 质量分 |
| 应用架构 | core 造脏数据/三类处理/质量分；pipeline 编排并留痕 |
| 技术架构 | Python 3.12 + conda ai01；numpy/pandas；pytest |

## 分层与模块职责
| 模块 | 职责 | 关键接口 |
|---|---|---|
| `core.py` | 造脏/三类处理/质量分 | `make_dirty()/clean()/quality()` |
| `pipeline.py` | 清洗→留痕→报告 | `run(cfg, out_dir)` |

## 依赖方向
```
run.py  →  pipeline  →  core（纯函数，零依赖）
               ↓           ↑
            io_utils ←── report
               ↑
            config（YAML 驱动）
```
**规则**：下层不得反向依赖上层；`core` 不 import `io_utils`（保持可单测）。

## 关键质量属性
- **可测试性**：core 为纯函数 → 单测无需 mock 文件系统
- **可配置性**：阈值全部外置 YAML
- **可复现性**：种子固定于配置
