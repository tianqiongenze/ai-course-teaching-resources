# 02 架构说明（TOGAF 四域视角）

> 项目：轴承剩余寿命预测

| TOGAF 域 | 本项目答案 |
|---|---|
| 业务架构 | 预测性维护排程：把'坏了再修'变成'提前一个周期换件'；四档验收由实测判定 |
| 数据架构 | 真实轴承 npz（30 台 × 180 窗 × 20 列窗口特征）→ 归一化 RUL 标签；设备级留出，同一设备只在一侧（防泄漏）；npz 不在盘时同口径合成兜底并标注来源 |
| 应用架构 | core 数据加载/切分/LSTM/对照模型/拐点/敏感性/绘图；pipeline 真跑并把这些实测值喂给 tiers 判档；report/cli 呈现 |
| 技术架构 | Python 3.12+（实跑 3.14.6）+ conda ai01；numpy/scikit-learn/matplotlib 必需，torch 决定 LSTM 主路径，PyYAML/pycodestyle 缺失有内置兜底；pytest |

## 分层与模块职责
| 模块 | 职责 | 关键接口 |
|---|---|---|
| `core.py` | 数据加载/切分/训练/拐点/敏感性/图表落盘/产物字节 | `load_dataset()/split_devices()/train_lstm()/model_table()/knee_analysis()/window_sensitivity()/plot_*/artifact_stat()` |
| `tiers.py` | 工单四档判定（纯函数，只比较实测值） | `TIERS/KEYS/MANUAL/verdict()/render_lines()` |
| `pipeline.py` | 真跑全流程 → 报告段 + result.json | `build(cfg, out_dir)`、`run(cfg, out_dir)` |
| `stylecheck.py` | PEP 8 规范率实测（pycodestyle 或内置兜底） | `scan_project()/augment()/format_section()` |
| `cli.py` | 命令行（`--tier` 打印实测档位，无自宣言常量） | `main(argv)`、`env_check()` |
| `config.py` / `io_utils.py` / `report.py` | YAML 加载 / 原子写与表格 / 报告渲染 | `load_config()` / `write_json()` `course_data()` / `save()` |

## 依赖方向
```
run.py  →  cli  →  pipeline  →  core（领域算法）→ io_utils（数据路径/落盘）
                     ↓            ↑
                   tiers        report
                     ↓            ↑
                 stylecheck ←── config（YAML 驱动）
```
**规则**：下层不得反向依赖上层；`tiers.py` 是纯函数（不 import 任何第三方库、
不读文件、不产生数据），因此判档可离线单测、删能力必然降档。
`core.py` 只做"读数据路径 + 落盘产物"这一层 IO 协作（`io_utils.course_data`、
`artifact_stat`），业务算法仍保持纯函数可单测。

## 关键质量属性
- **可测试性**：core/tiers 为纯计算 → 单测无需 mock 文件系统（除产物字节断言）
- **可配置性**：门槛数字与实验清单全部外置 YAML；工单数字与"兜底口径"分节标注
- **可复现性**：种子固定于配置，torch/sklearn 均设 random_state，两轮实测逐项一致
- **诚实性**：库缺失或指标算不出 → 传 None/False → 判缺 + 报告印 MISS，不冒充达标
